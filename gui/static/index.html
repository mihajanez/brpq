Test case

Instances from data/. The file name encodes tiers–stacks–index, e.g. data03-06-29 = 3 tiers, 6 stacks. Instances you design and save appear as custom/….

Editing your own bay in the Instance designer on the right. It runs like any other test case, and saving puts it in data/custom/.

Parameters

Blank means "don't pass the flag" — the solver default applies.

Height limit = tiers in the file + this many extra tiers. The usual CV-benchmark setting is 2; ZQLZ instances use 0. Blank = no height limit (stacks may grow to the number of blocks).

Absolute cap on stack height. It never lowers the limit set by -E or by the tallest stack in the file — it only raises it.

Wall-clock budget for the optimisation. On a timeout you get the best bounds found so far instead of a proven optimum.

Gurobi threads. 0 or blank lets Gurobi use every core.

How aggressively relocation sequences are expanded into IP variables. Higher = a bigger, tighter model; lower = a smaller model and more iterations.

Skips the fast heuristic that seeds an initial upper bound.

Solves lower bounds only, without the upper-bounding loop.

Echoes the instance and progress details into the log tab.

Writes the QUBO formulation to qubo/<test case>.qubo and loads it into the Quantum tab. Classical results are unaffected.

Load a .qubo file exported with -Q into the Quantum tab: the matrix, D-Wave annealing and QAOA. A run with Also export QUBO loads its export automatically.

    1 · QAOA circuit
    
            qiskit.circuit.library.qaoa_ansatz
          
    
          
    The QUBO becomes an Ising cost Hamiltonian
            H = Σ hi Zi + Σ Jij ZiZj
            on one qubit per column (a measured 1 = column selected). Each of the p layers
            applies the cost phase e−iγH (RZ and RZZ gates) and the mixer
            e−iβΣX (RX gates), starting from the uniform superposition.

    3 · Simulate classically
    
            Qiskit Aer statevector · SciPy optimiser
          
    
          
    
            
            
            
            
            
            
            
            
          
    
          
          
    The angles are tuned on the exact statevector (or on sampled shots), then
            the tuned circuit is sampled — ideally, or through a device noise model. Noisy simulation is
            slow (tens of ms per shot), so it is used for the final sampling only. CVaR α < 1
            optimises the best α-fraction of outcomes instead of the mean.
